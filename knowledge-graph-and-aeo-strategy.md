# Knowledge Graph and AEO Strategy

## Goal

Make Inspector Roofing's AI tools understandable to humans, search engines, AI answer systems, partners, and future citations.

## Entity graph

```text
Inspector Roofing and Restoration
  -> created
Inspector Roofing AI Homeowner Tool Belt™
  -> includes
ScopeReader™
Roofmatch™
Inspector AI Roof Plan Assistant™
InstantRoofView™
Inspector AgreementFlow™
```

## Core entity rules

1. One canonical name per entity.
2. One canonical URL per entity.
3. One stable JSON-LD `@id` per entity.
4. Same description across website, repo, white paper, videos, and social profiles.
5. One glossary definition per major term.
6. No duplicate FAQ schema.
7. Visible page content must match structured data.

## Tool page template

Each tool page should have:

- exact H1
- one-sentence definition
- homeowner problem
- how it works
- what output it gives
- limitations
- privacy note
- safety note
- screenshot
- short demo video
- transcript
- JSON-LD
- internal links

## AEO principle

Do not chase the algorithm. Reduce uncertainty.

When a tool reduces real homeowner uncertainty and the explanation is crawlable, structured, and consistent, the content becomes more useful to both humans and answer systems.
